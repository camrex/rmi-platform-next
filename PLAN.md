## Phase B2 — core services (PROPOSAL §3.1, §4, §6.1, §10 phase 2)

Conventions for every B2 task (local tiers: this block and the task line are your reading list):
- Code goes in `core/src/rmi_core/<service>/` (package: `__init__.py`, `models.py`, `service.py`, `web.py`
  only as needed); tests in `core/tests/test_<service>*.py`. Files ≤ 500 lines; pyright strict; no module key
  (`sbis`, `civ`, `cvs`, `tivs`, `pm`, ...) in `core/src` (`make check-core-clean`). A pure function gets plain
  unit tests; anything with a table gets an async DB test using `db_session` (docs/TESTING.md).
- **Core chain** (from B2.7): `core/src/rmi_core/migrations/`, schema `core`, version table
  `alembic_version_core`. Models subclass `rmi_core.base.Base` (its `metadata` has `schema="core"`) and are
  imported by `migrations/metadata.py`, so `make check-migrations` sees no drift. A task that adds tables adds
  one revision file `versions/NNNN_<slug>.py` (`revision = "NNNN_<slug>"`, `down_revision` = the file before
  it) and the matching model import. Tables are created by revisions only, never `create_all`. Use `Mapped[...]`
  columns, `uuid` primary keys (`default=uuid.uuid4`) unless the task says otherwise, `timestamptz` times, closed
  vocabularies as `StrEnum` + a CHECK constraint (PROPOSAL §5).
- Everything a service needs from the manifests arrives as a `LoadedModules` argument (B1.10); a service never
  calls `load_modules()` itself (only the two roots do, B2.10 and B2.28).
- Done = the task's tests plus `~/.local/bin/make check` green. Tick the task, journal it.
- Not in B2, on purpose: conversations (ADR 0019), documents, storage (ADR 0012), `Presence` and the GIS
  sync (B3), write-back (B12): each is built when the first module that needs it is ported. No Redis server on
  this box (`which redis-server` finds none): ARQ code is tested without one (B2.27); a live-broker test skips
  unless `RMI_REDIS_URL` is set. The operator can install Redis later; nothing else waits on it.
